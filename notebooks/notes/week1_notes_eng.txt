Difference between quantum cryptography and post-quantum cryptography:
Quantum Cryptography – protection using quantum physics (photons of light, cool equipment).
Post - quantum Cryptography – protection using new mathematical problems (such as ML - KEM ), unsolvable by hackers and quantum supercomputers. Works on regular phones and computers. A software-based method for protecting against threats.

RSA :
Rivers–Shamir–Adleman algorithm.
A public-key encryption algorithm based on the factorization problem—the decomposition of a large number into two prime factors.
Example (factorization): Multiplying two huge prime numbers (say, hundreds of digits long) is very easy—a computer can do it in a split second. The result of the multiplication becomes the public key. But the inverse problem— taking this huge number and figuring out which two prime numbers it was derived from—is incredibly difficult.

Elliptic curve cryptography ( ECC ):
Public-key encryption algorithm using graphs.
Example (discrete logarithm): It's like a convoluted route. It's easy to follow a million steps according to a certain rule and arrive at point B. But if you give a regular computer only point B, it won't be able to guess exactly how many steps you took or which path you took.
As secure as RSA , but the keys are shorter.

Shor's algorithm:
Uses quantum properties (superposition and interference) to find hidden mathematical patterns (periods) within numbers. It causes incorrect answers to "cancel" each other, while the correct answer "amplifies."
Unlike regular computers, it breaks RSA and ECC in hours.

Symmetric cipher:
The same key is used for both encryption and decryption.
Analogy: Imagine you have a safe and two identical keys. You keep one key, and you gave the other to your friend Bob. You put a secret letter (message) in the safe, lock it with your key, and mail the safe to Bob. Bob receives the safe, takes his key (the same as yours), opens it, and reads the letter.
Works quickly.
How to securely transmit the key initially?
Encrypts the data itself, not the key.

KEM ( Key Encapsulation Mechanism ):
Create and distribute a shared symmetric key.
Allows two parties to securely agree on a shared secret key.
Analogy:
	Bob buys a padlock, keeps the key for himself (the Secret Key), and mails you the unlocked, unlatched padlock (the Public Key).
	You come up with a complex password (a symmetric key), put it on a piece of paper in a metal box, and attach Bob's open lock to it. Snap it shut! (This is the encapsulation process.)
	Now the box can't be opened without Bob's key. You send it back.
	Bob receives the box, opens it with his private key and takes out a piece of paper with the password you created (This is the decanculation process).
Now you both have a shared secret password, and no hacker who intercepts the box along the way will be able to find it out!
Encrypts the key itself.
KEM is very long due to complex mathematics and is only used to encrypt keys.
KEM consists of KeyGen , Encaps and Decaps .
KEM is a type of asymmetric algorithm. The difference: with an asymmetric key, you create your own secret password, while with KEM, a function creates one for you.

As a rule, KEM and a symmetric key work in pairs (you put a symmetric key in the box and encrypt the box using KEM ).

ML-KEM parameter sets:
ML-KEM-512 ( basic level ):
Short keys, works quickly. Suitable for low-power devices. Matrix size A 2x2.
ML - KEM -768 (recommended standard):
Medium level of protection, slightly larger keys, longer life. Internet protection (browsers, instant messaging). A-sensor size 3x3.
ML - KEM -1024 (maximum protection):
Long keys, slow operation. High-security data protection (bank archives). A-size matrix 4x4.
The degree of a polynomial is always n=256.

Key generation KeyGen → ( pk , sk ):
Preparing the lock and key.
pk ( Public Key ) – a public key, an unlocked safe lock, can be sent to the interlocutor.
sk ( Secret Key ) – a secret key, the only key to the lock, which the recipient keeps for himself.

Encaps ( pk ) ( c , K ):
Creation and safe packaging of a secret.
The sender takes the public key (lock) and:
Generates a random shared secret K ( Key ) – a symmetric password.
Creates a ciphertext c ( Ciphertext ) – a box in which K is encrypted with pk .

Decaps ( sk , c ) → K :
Opening and extraction of secretion.
The receiver receives c and extracts K ' from it using his sk .
Ideally K = K'.

Now both Alice and Bob have the same secret K .

The recipient (Bob) is the one who needs the information and sends the safe.
Sender (Alice) is the one who sends the information in the safe.

Terminology:
Key roles and processes
	party (party) — a participant in the exchange (for example, Alice or Bob).
	key establishment (key establishment) is a procedure by which parties obtain shared secret material.
	key A pair (key pair) is a set of two keys: one can be made public, the other must be kept secret.
KEM keys
	encapsulation Key (encapsulation key) – created during key generation and used in the encapsulation process. Can be public (like a "public key").
	decapsulation key (decapsulation key) - also created during generation, but must be kept secret and destroyed when no longer needed (it's like a "private key").
	( KEM ) ciphertext - the bit string resulting from encapsulation and used as input for decapsulation.
Processes
	Encapsulation is the process by which a shared secret key and associated ciphertext are generated based on an encapsulation key and randomness.
	Decapsulation is the process by which a shared secret key is recovered from the ciphertext and the decapsulation key.
Keys for PKE (public key encryption, component K - PKE )
	encryption key (encryption key) - can be made public.
	decryption key (decryption key) - must be kept private and destroyed after use.
(Important: The document specifically avoids the terms " public key " / " private key " to avoid confusion—these more specific names are always used instead.)
Secrets
	shared secret (shared secret) - a secret value calculated during the key establishment process, known to both parties.
	shared secret key (shared secret key) - a shared secret that can be used directly as a cryptographic key (without additional processing).
Security terms
	destroy (destroy) - after the destruction of classified data, no information about it can be recovered.
	hash function (hash function) is a function with a fixed-length output that has the following properties:
	one - way (unidirectional) - it is impossible to find an input that gives a given output;
	collision - resistant - it is impossible to find two different inputs with the same output.
	pseudorandom (pseudo-random) is a process that is deterministic (that is, not actually random), but appears random if you don’t know its internal structure.
	public channel (open channel) - a communication channel that can be observed (and even interfered with) by third parties.
	input checking (input data verification) - checking that the input of the algorithm meets the requirements.
Other
	little - endian — the order of bytes/bits, where the leftmost (first) bit/byte is the least significant.
	security category / security strength (security category/degree) is a numerical characteristic of how many computing resources are needed to crack an algorithm.
	shall / should is an important distinction in the standard text:
	shall = mandatory requirement;
	should = a strong recommendation, but not mandatory (ignoring it may lead to problems).

to build a real working circuit from the MLWE mathematical problem:
	Step 1: From the MLWE problem , a regular public-key encryption ( PKE ) scheme is constructed—it is called K - PKE .
	Step 2: This PKE scheme is "improved" using a special mathematical transformation— the Fujisaki - Okamoto ( FO ) transform . This transforms the standard encryption into full-fledged KEM with stronger security guarantees.
